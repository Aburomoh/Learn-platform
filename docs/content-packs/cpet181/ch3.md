## 1. Logical vs physical addresses — s.2 — CORE
Logical (virtual) = generated by the CPU; physical = location in RAM. Benefit: the OS can place and move
a process without changing its logical addresses, which helps against fragmentation. Logical space ≥
physical space; the MMU maps one to the other.

## 2. Non-contiguous allocation; the two methods — s.3–4 — CORE
Program pieces may sit anywhere in memory; needs cooperation of memory manager and hardware. Methods:
paging and segmentation.

## 3. Paged memory allocation — s.5–7, s.10 — CORE + WORKED
Memory in fixed **frames**, program in fixed **pages**, page size = frame size (= disk section size) to
avoid fragmentation. Before running: count the pages, find enough free frames, load all pages (s.6).

|---|---|---|

## 7. Paging: advantages and disadvantages — s.14 — CORE
Plus: efficient use of memory, no external fragmentation, simple algorithm. Minus: address resolution
overhead (more with multilevel paging); internal fragmentation remains in the last page.

## 8. Segmented memory allocation — s.15–17 — CORE + WORKED
Job split into segments of **different** sizes, one per logical module (user's view); memory allocated
dynamically, not in frames; each segment numbered; tables: JT (one for the system), SMT (one per job),
MMT (one for the system); address = segment number + displacement.

s.17 SMT for Job 1 (segment, size, memory address): 0 main program 350 at 4000; 1 subroutine A 200 at
7000; 2 subroutine B 100 at 6000. OS occupies 0–3000, 3000–4000 empty.

| Reference | Segment, displacement | Physical | Verified |
|---|---|---|---|
| Main program line 50 (call A) | 0, 50 | 4000 + 50 = **4050** | ✓ |
| Main program last line | 0, 349 | **4349** | ✓ |
| Subroutine A line 100 (call B) | 1, 100 | 7000 + 100 = **7100** | ✓ |
| Subroutine A last line | 1, 199 | **7199** | ✓ |
| Subroutine B last line | 2, 99 | **6099** | ✓ |

SMT also lists protection, referenced, modified and status columns (not used in any example).
Segmentation plus (s.18): no internal fragmentation, dynamic growth and linking. Minus: variable-length
segments are hard to manage on disk; segment size limited by memory.

## 9. Paging vs segmentation; virtual memory — s.19–20 — CORE
| | Paging | Segmentation |
|---|---|---|
| Internal fragmentation | Yes, inside frames | No |
| External fragmentation | No | Yes |
| Pieces | Equal pages | Unequal segments |
| Address | Page number + displacement | Segment number + displacement |
| Table | PMT | SMT |

Virtual memory plus: job size not limited by memory, better use of memory, unlimited
multiprogramming, no external and little internal fragmentation. Minus: hardware cost, software
complexity to prevent thrashing (word only, not explained).

## 10. Internal vs external fragmentation — s.21 — CORE
| | Internal | External |
|---|---|---|
| Blocks | Fixed size | Variable size |
| Cause | Process smaller than its block | Processes removed, leaving holes |
| Remedy | Best-fit block | Relocation (compaction) and paging |
| Occurs with | Paging, fixed partitions | Segmentation, dynamic partitions |

## 11. Cache memory — s.22–25 — CONTEXT
Small fast memory between CPU and main memory for frequently used data and instructions; filled in a way
similar to paging. Design factors: cache size, block size, replacement algorithm, rewrite policy (named
only). s.24: early computers had registers → main memory → secondary storage; modern CPUs add cache next
to the registers. s.25 table of typical capacity and access time (registers ~1 clock cycle, cache 1–2,
main memory 1–4, magnetic disk microseconds, optical up to a second, tape seconds); a clock cycle is the
smallest unit of processor time. No access-time calculation is taught.
